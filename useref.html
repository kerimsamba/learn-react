03 · useRef
useRef

A box that survives renders

Hold onto a value without triggering a re-render when it changes — or grab a real DOM element to control it directly.

In plain words

const ref = useRef(initialValue);
ref.current // 👈 read or write the value here
  • It's a plain box with one property: .current.
  • Changing .current does not re-render — unlike state.
  • The box stays the same across every render (it remembers).
📌
Like a sticky note on your desk. You can scribble on it any time, it stays put between tasks, but updating it doesn't redraw the whole desk.

Try it

Control an input directly

A ref attached to an element lets you call browser methods like .focus() on it. 

const inputRef = useRef(null);

return (
  <>
    <input ref={inputRef} />
    <button onClick={() => inputRef.current.focus()}>Focus</button>
  </>
);

state re-renders · ref does not

state count: 0
ref count: 0
renders: 1
Tap +1 ref a few times — the displayed ref count seems stuck at 0, because nothing re-rendered. Now tap +1 state: the screen redraws and the ref's true value suddenly appears. The value was there all along; it just wasn't shown until a render happened. 
const [count, setCount] = useState(0); // re-renders
const clicks = useRef(0);            // silent

clicks.current++;        // updates the box, screen unchanged
setCount(count + 1);    // triggers a re-render → both now show

Good to remember

  • Need it on screen? Use useState. Just need to remember it? useRef is lighter.
  • Common uses: focusing inputs, storing a timer/interval id, holding the "previous" value, counting things that don't affect the UI.
  • Don't read/write .current during rendering — do it in event handlers or effects.
