useEffect

Run side-effects

Use it for things that reach outside your component: fetching data, timers, subscriptions, updating the document title.

In plain words

useEffect(() => {
  // runs AFTER React paints the screen
  return () => {
    // optional cleanup, runs before the next effect / on unmount
  };
}, [dependencies]);

The dependency array is the key. It tells React when to run the effect again:

  • No array → runs after every render.
  • [] empty → runs once, when the component first appears.
  • [count] → runs whenever count changes.
🔔
It's a "when this changes, do that" rule. You list what to watch; React rings the bell only when one of those things actually changes.

Try it

Choose what the effect depends on

count: 0
other: off

Try each mode. With [count], changing "other" re-renders but the effect doesn't run — because count didn't change. 

useEffect(() => {
  console.log("effect ran, count is", count);
}, [count]); // 👈 try [], or remove the array

A timer that cleans up after itself

0seconds
not mounted
Without the cleanup return, the interval would keep running forever (a memory leak). React calls your cleanup when the component goes away. 
useEffect(() => {
  const id = setInterval(() => setSecs(s => s + 1), 1000);
  return () => clearInterval(id); // 👈 cleanup
}, []);

Good to remember

  • Effects run after the render is on screen, not during it.
  • List every value the effect uses in the dependency array. Leaving things out causes stale data bugs.
  • Return a cleanup function for anything ongoing: timers, event listeners, subscriptions.
  • Don't put updating state inside an effect that depends on that state without care — you can create an infinite loop.
