04 · useContext
useContext

Share without passing props

Some data — the theme, the logged-in user, the language — is needed all over the app. Context lets deep components read it directly.

In plain words

// 1. create a context
const ThemeContext = createContext("light");

// 2. provide a value high up
<ThemeContext.Provider value={theme}> … </ThemeContext.Provider>

// 3. read it anywhere below, no props needed
const theme = useContext(ThemeContext);
📻
The Provider is a radio broadcast. Any component below can tune in with useContext — no need to hand the message down person by person.

Try it

One switch, deep effect

light

The <Button> at the bottom reads the theme straight from context. The Page and Toolbar in between don't know or care about it. 

function Button() {
  const theme = useContext(ThemeContext); // 👈 direct
  return <button className={theme}>I follow the theme</button>;
}

Watch how the value travels

With prop drilling, every layer must accept and forward user, even ones that don't use it. With context, the middle layers stay clean and only the consumer reads it.

Good to remember

  • Great for "global-ish" data: theme, current user, language, etc.
  • When the Provider's value changes, every consumer re-renders. Don't shove fast-changing data through one giant context.
  • It's not a state manager by itself — usually you pair it with useState or useReducer to hold the value.
