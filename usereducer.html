useReducer

State with clear actions

When state gets complex or updates in many ways, useReducer keeps the logic in one tidy place. Think of it as useState's organised sibling.

In plain words

const [state, dispatch] = useReducer(reducer, initialState);

// reducer = (currentState, action) => newState
function reducer(state, action) {
  switch (action.type) {
    case "increment": return { count: state.count + 1 };
    case "reset":     return { count: 0 };
    default:          return state;
  }
}

dispatch({ type: "increment" }); // 👈 send an action
🏧
Like an ATM: you don't reach in and move the cash yourself. You send a request ("withdraw 20"), and one trusted machine decides the new balance.

A list managed by one reducer

Add, tap to toggle done, or remove. Each is a small action — add, toggle, remove — handled by the same reducer. 

case "add":    return [...state, { id, text, done: false }];
case "toggle": return state.map(t =>
                   t.id === action.id ? { ...t, done: !t.done } : t);
case "remove": return state.filter(t => t.id !== action.id);

useState or useReducer?

  • useState for simple, independent values (a toggle, an input, one number).
  • useReducer when updates are complex, related, or the next state depends on the old one in many ways.
  • The reducer must be pure: given the same state + action, always return the same new state, with no side-effects.
  • Always return a new object/array — never mutate the old state.
