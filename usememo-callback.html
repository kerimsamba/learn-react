06 · useMemo / useCallback
useMemo · useCallback

Skip needless work

Two performance helpers. useMemo remembers a computed value; useCallback remembers a function — so they aren't rebuilt on every render.

In plain words

// remember a value; recompute only when [a, b] change
const total = useMemo(() => expensive(a, b), [a, b]);

// remember a function; rebuild only when [a, b] change
const onClick = useCallback(() => doThing(a, b), [a, b]);
🧮
Like writing a hard sum's answer on a sticky note. Next time you're asked, you read the note instead of doing the maths again — unless the numbers changed.
Don't reach for these first. Most components are fast enough without them. Add them only when you measure a real slowdown, or when a value/function is fed to a memoized child.

Try it

An "expensive" calculation

number: 3
theme clicks: 0
result: … computations: 0

With memo on, the "unrelated re-render" button doesn't recompute (the count stays still). Turn it off and every render redoes the work. 

const result = useMemo(
  () => slowCalculation(number), // only runs…
  [number]                       // …when `number` changes
);

A stable function for a memoized child

Parent renders: 1
<Child> renders: 1 child is stable
A child wrapped in React.memo skips re-rendering when its props are unchanged. But a function created fresh each render is a new prop every time — useCallback keeps the same function so the child can safely skip. 
const handleClick = useCallback(() => { … }, []);
// Child is React.memo(...) → only re-renders if handleClick changes
<Child onClick={handleClick} />

Good to remember

  • useMemo returns a value; useCallback returns a function. In fact useCallback(fn, d) is just useMemo(() => fn, d).
  • They're a cache, not a guarantee — React may still recompute. Never rely on them for correctness, only speed.
  • Get the dependency array right, same as useEffect. Missing deps → stale results.
  • Premature use adds complexity for no gain. Measure first.
