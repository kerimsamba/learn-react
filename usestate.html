useState

Remember a value

The most common hook. It gives your component a piece of memory and re-draws the screen whenever that memory changes.

In plain words

You ask React for a value and a way to change it:

const [count, setCount] = useState(0);
  • count — the current value.
  • setCount — call it to change the value. This also tells React to re-render.
  • 0 — the starting value (only used the very first time).
🔢
Like the score counter in a game: it holds a number, and updating it instantly refreshes the scoreboard on screen.

Notice: every change to state re-renders the component (watch the log). React then updates only the parts of the screen that actually changed. 

function Counter() {
  const [count, setCount] = useState(0);
  const [name, setName]  = useState("");

  return (
    <div>
      <h1>{count}</h1>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <input value={name} onChange={(e) => setName(e.target.value)} />
      <p>Hello, {name || "stranger"}</p>
    </div>
  );
}

Why "+3" sometimes only adds 1

0
The wrong way calls setCount(count + 1) three times in one click. All three see the same old count, so they all set it to the same number → it only goes up by 1.
The right way passes a function: setCount(c => c + 1). React feeds each call the latest value, so three calls really add 3. Use this form whenever the new value depends on the old one. 
// ❌ all three read the same stale `count`
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);

// ✅ each call gets the latest value
setCount(c => c + 1);
setCount(c => c + 1);
setCount(c => c + 1);

Good to remember

  • Don't change state directly. Use the setter — count++ won't re-render; setCount(count + 1) will.
  • State updates aren't instant. The new value shows up on the next render, not the line after you call the setter.
  • For objects/arrays, make a copy. e.g. setUser({ ...user, name }) instead of mutating user.
  • Each call to the hook is independent. A component can have as many useStates as it needs.
